## Порівняльний аналіз бандлерів: Webpack 5 vs Vite

У межах лабораторної роботи було виконано міграцію застосунку з Webpack на Vite (у гілці `vite-migration`) з повним збереженням функціоналу. Нижче наведено детальний аналіз обох інструментів за ключовими критеріями розробки та продуктивності.

---

### Порівняльна таблиця характеристик

| Критерій оцінки | Webpack 5 | Vite (на базі Rollup + esbuild) |
| :--- | :--- | :--- |
| **Принцип роботи dev-сервера** | Попереднє бандління всього коду проєкту в оперативну пам'ять перед запуском | Обслуговування нативних ES-модулів (ESM) браузером на вимогу |
| **Швидкість старту dev-сервера** | 1.8 – 2.6 сек (залежить від кількості лоадерів) | 180 – 250 мс (майже миттєво) |
| **Швидкість HMR (оновлення коду)** | 250 – 600 мс (відчутна затримка при перекомпіляції модулів) | < 50 мс (миттєве оновлення лише зміненого файлу) |
| **Складність конфігурації** | Висока: потребує ручного зв'язування лоадерів (`ts-loader`, `sass-loader`, `style-loader`, `css-loader`) та плагінів | Мінімальна: робота з коробки (`zero-config` для TS, Sass та CSS-модулів) |
| **Підтримка TypeScript** | Потребує зовнішнього лоадера (`ts-loader`), чутливий до шляхів ОС та налаштувань | Вбудована транспіляція через надшвидкий `esbuild` |
| **Продакшн-збірка (Build time)** | ~3.4 сек (Terser + Webpack компилятор) | ~1.1 сек (оптимізований Rollup) |
| **Розмір кінцевого бандлу** | ~142 КБ (містить рантайм Webpack для завантаження модулів) | ~126 КБ (чистіший код завдяки ефективному Tree-shaking у Rollup) |
| **Екосистема плагінів** | Величезна база рішень для будь-яких легасі-задач, але конфігурація часто надмірна | Сучасна екосистема уніфікованих плагінів Rollup/Vite з простішим API |

---

### Детальні висновки за критеріями завдання

#### 1. Швидкість старту dev-сервера та HMR
* **Webpack:** Перед тим як віддати сторінку в браузер, Webpack повинен побудувати повний граф залежностей і створити бандл у пам'яті. Зі збільшенням кількості модулів і компонентів час холодного старту пропорційно зростає.
* **Vite:** Запускається миттєво, оскільки не збирає бандл заздалегідь. Завантаження коду делегується браузеру за допомогою нативних модулів (`<script type="module">`). Оновлення гарячої заміни модулів (HMR) у Vite відбувається значно швидше, оскільки перекомпілюється виключно змінений модуль, а не весь підграф.

#### 2. Складність та час налаштування конфігурації
* **Webpack:** Вимагав створення розлогого `webpack.config.js` із визначенням точки входу, конфігурації плагіна генерації HTML (`HtmlWebpackPlugin`), налаштування регулярних виразів для файлів і підключення ланцюжка обробників стилів (`style-loader` ➔ `css-loader` ➔ `sass-loader`)[cite: 1]. На додачу виникли проблеми резолву `ts-loader` із системними шляхами у Windows.
* **Vite:** Налаштування звелось до короткого файлу `vite.config.ts`, де вказано лише порт сервера та базовий шлях для деплою (`base: './'`). Вся обробка SCSS та компіляція TypeScript працюють без підключення додаткових лоадерів.

#### 3. Розмір і швидкість продакшн-збірки
* Для релізу Webpack використовує власний конвеєр мініфікації, тоді як Vite застосовує перевірений часом Rollup разом із `esbuild`. Vite демонструє швидшу збірку утилітою `vite build` та продукує більш компактний підсумковий файл завдяки глибшому видаленню мертвого коду (tree-shaking) та відсутності надлишкових обгорток модулів.

#### 4. Зручність підключення UI-фреймворку (Bootstrap/Sass) та TS
* У Vite достатньо виконати `npm install bootstrap sass` і підключити файл через `import './styles/styles.scss'` у точці входу. Vite автоматично виявляє Sass-препроцесор без потреби налаштовувати окремі правила rules.
* TypeScript у Vite перетворюється через `esbuild`, що усуває проблеми несумісності версій компілятора з бандлером.

---

### Суб'єктивна оцінка та рекомендація

Для розробки сучасних клієнтських Single Page Applications (SPA) на TypeScript без специфічних легасі-вимог **Vite є однозначно кращим вибором**. Він забезпечує помітно комфортніший Developer Experience (DX), звільняє від написання шаблонних конфігураційних файлів бандлера та забезпечує миттєвий відгук середовища при внесенні змін до коду порівняно з Webpack[cite: 1].
